Project 01 · Futures data

IQFeed Downloader

A single Rust binary that pulls IQFeed's back-adjusted continuous futures and writes one CSV per market per timeframe. Hourly bars come straight from IQFeed; daily bars are built from them by trade day, so they line up with the CME Globex session.

  • Full refresh by default. Back-adjusted history changes at every roll, so appending to an old file would mix adjustment bases.
  • Shrink guard. A new download replaces a file only if it keeps at least 90% of the existing rows. A truncated response never overwrites good history.
  • Atomic, repeatable writes. Files are written to a temp file, verified, then renamed. The same data gives a byte-identical file.
  • Built for unattended runs. Waits for IQFeed to log in, retries, and writes a per-symbol report with clear exit codes.

Micro futures covered: MES, MNQ, MYM, M2K, MCL, MGC

Project 02 · Crypto data

Kraken Downloader

Builds a local dataset of daily OHLCV candles for every USD-quoted crypto pair on Kraken. It uses public endpoints only, so no API keys are needed.

  • Full history from two sources. Kraken's REST endpoint returns only the latest 720 candles, so older history is imported from Kraken's bulk files and the API keeps it current.
  • Delisted pairs included. Pairs that no longer trade are kept, so backtests are not skewed by survivorship bias.
  • Exact values. Prices and volume are stored as the decimal strings Kraken sends, with no float rounding. The still-forming day is never written.
  • Verify command. Checks for gaps, bad timestamps and invalid bars, and compares stored candles against the live API.

# one-time history import, then daily updates

Project 03 · Orchestration

Real Test Pilot

A desktop app and always-on service that runs the daily data pipeline for RealTest. It is growing into a full strategy registry, performance monitor and order executor.

  1. 1DownloadFutures at 17:30 New York on weekdays; Kraken at 00:10 UTC daily.
  2. 2ValidateStale bars, gaps, bad highs and lows, and outsized one-day moves raise alerts.
  3. 3SyncPublishes daily bars to the RealTest data folders in one common layout.
  4. 4ImportRuns the RealTest import so every backtest starts on today's data.

How it is built

  • Service first. Scheduling lives in a headless service, not in the window. Closing the app hides it to the tray and the pipeline keeps running.
  • Catch-up and retry. A run missed while the PC was off starts when the service does. A failed run is retried once.
  • One UI, two ways in. The same React interface runs in the Tauri desktop app and in a browser, with token-protected remote access over Tailscale.
  • Everything recorded. Each run is stored in SQLite with its status, logs and data-quality results.
